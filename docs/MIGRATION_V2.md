# v2 数据迁移与恢复

本指南适用于从旧版记忆表升级到画像（`profile_items`）与事件（`event_items`）分库结构。当前代码是待验收候选版本，尚未发布。

## 升级前的备份

首次打开已有数据库时，插件在修改表结构前使用 SQLite 在线备份 API 生成同目录的 `tmemory.db.pre-v018.sqlite3`。这样能包含已提交的 WAL 内容；不要只复制正在运行的主数据库文件。旧配置在旧键原地迁移前另存为 `tmemory.db.pre-v018.config.json`。请同时保留原插件版本。若上述备份失败，先停止升级并保存现有数据，不要继续写入。

## 迁移与隔离

迁移记录在 `storage_migrations` 中，旧数字 ID 由 `legacy_record_map` 映射。新对象公开 ID 使用 `p:<id>`（画像）或 `e:<id>`（事件）；操作时保留前缀。历史记录只有在来源、平台实例和范围可以确定且通过安全检查时才成为活跃记忆。来源模糊、疑似指令注入的内容进入待审区；凭据脱敏，不能直接激活。私聊和各群默认隔离，身份绑定不会自动共享范围；人格也分别隔离。

迁移后检查 `storage_migrations` 的版本 18 报告，其中包含画像、事件和隔离数量。抽查旧 ID 映射、事件日期与任务状态，并在管理页审核待审数据。待审数据不会进入自动召回。

## 导出与导入

新导出格式为 `schema_version: 2`，包含画像、事件及关联业务数据；向量和缓存索引可以重建，不作为备份。导入支持 v2，也兼容 v1 输入，统一执行校验。先运行预览，再应用导入；重复导入会做去重，导入的提醒默认暂停。升级后的导出为 v2，不保证能由旧版插件读取。

## 回退边界

切换新版写入**之前**，可以停止插件、核对备份并恢复旧数据库和旧插件版本。切换新版写入**之后**，先暂停写入并再次备份当前数据库，再做向前修复；直接恢复旧快照会丢掉升级后新增的记忆。任何恢复都应在隔离环境核对业务数据和引用，再恢复运行。

## 验收状态

本仓库的自动化测试与本地 AstrBot 加载验收只覆盖其报告明确列出的版本和路径。Dashboard 浏览器权限、真实平台账号收发、用户生产数据库迁移必须在目标环境单独验证；未验证项不能写成已通过。
